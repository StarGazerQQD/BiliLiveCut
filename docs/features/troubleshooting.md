# 故障排查

Portable 与源码启动均保留 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 及对应小写变量，外部模型、平台和下载请求使用各客户端支持的代理配置。API 启动时合并 `NO_PROXY` 与 `no_proxy`，保留全部用户条目并追加 `127.0.0.1`、`localhost`、`::1`，两种拼写保持一致。Launcher 的本地就绪探测直接连接回环地址。使用 SOCKS 代理时，运行环境需要相应客户端的 SOCKS 依赖；代理设置错误仍报告真实连接错误。`getaddrinfo failed` 表示域名解析失败，需结合当次请求的 DNS、代理和网络状态排查，不能仅凭此错误认定某一个原因。

Bilibili 录制以 `STREAM_QUALITY` 为画质上限，从高到低尝试：默认原画 `10000`、蓝光 `400`、超清 `250`、高清 `150`、流畅 `80`，并纳入接口声明的中间档位；每次画质协商最多请求 8 个不同档位，为标准低档保留预算。有可用地址即采用接口实际返回的 qn，同画质才按 `PREFERRED_STREAM_PROTOCOL` 选择协议；画质未知保留为空，不把请求值伪装为实际画质。确认直播中但所有档位均无地址时按取流临时故障重试，不解释为下播，也不为该房间失败设置平台限流。登录态、风控和网络错误按原有来源预算处理，不通过降画质绕过。录制重连重新获取临时地址，重试次数及时间上限仍有效；连续临时取流失败耗尽预算保留 ERROR 状态。只有 HTTP/TLS/TCP 日志明确出现 EOF 时才归为传输异常，普通 EOF 不证明本地媒体损坏。

优先提供程序版本、故障时间以及房间、场次或任务编号。Web 请求出现“服务处理失败”时，同时提供页面上的日志定位编号。后台“错误日志”保存 WARNING/ERROR 的安全异常链；`storage/logs/blc-<进程号>-<启动标识>.log` 还保留 DEBUG 信息及具体调用文件/行号。应用与 Uvicorn 服务器错误均进入同一诊断通道，访问日志不记录查询参数。两类日志使用同一脱敏规则，网络地址仅保留主机名，不记录签名路径、查询串、请求凭据或异常局部变量。提交前仍请检查个人路径等内容，不要上传 `.env`、数据库或模型缓存。

启动器、后端和前端分别写入独立日志，避免 Windows 中多个进程占用同一个文件而导致轮转报 `WinError 32`。每个文件达到 10 MB 后轮转并压缩为 ZIP；启动及轮转时清理超过 14 天的归档和已退出进程的日志，仍存活进程的未压缩日志继续保留。旧版 `blc.log` 与非项目日志不会自动删除。排错时收集故障时间附近各进程的 `.log` 和 `.log.zip` 文件；清理遭遇文件占用或权限错误时保留原文件并在控制台报告。

`blc doctor --yes` 使用当前 `FFMPEG_PATH`、`FFPROBE_PATH`、`STORAGE_ROOT` 和数据库配置检查环境。模型目录按运行时 `BLC_MODELS_DIR` 检查；未设置时明确提示使用 SDK 缓存。磁盘/内存读取失败代表未知，不代表剩余空间为零或资源充足。

录制的片段登记、stderr 排空或磁盘保护失败会结束当前录制并保留 ERROR 状态。弹幕本地故障只停止弹幕采集，记录实际确认到的覆盖时间。上传显示失败或待人工核对时，先核对平台结果；后台作业不会把这些状态当作上传完成。

| 现象 | 排查 |
|---|---|
| `ffmpeg 不是内部或外部命令` | 安装 FFmpeg 或在 `.env` 设置 `FFMPEG_PATH` |
| `check` 显示未开播 | 主播未直播时无流，属正常 |
| 取流报错 / 403 | 部分高清晰度需登录态，可在设置中心登录账号或填写 Cookie |
| 弹幕 token 返回 `code=-352` | 登录请求失败时会立即匿名兜底并定时重试；匿名请求也被风控时会按配置间隔重试，录制与实时转写继续。无需反复手动登录 |
| 片段未生成 | 看 `storage/logs/blc-*.log` 及其 ZIP 归档中的 `[ffmpeg]` 行 |
| ASR 主引擎未加载 | 确认 `pip install funasr modelscope` 已执行 |

## 模型请求与能力探测

文本和结构化调用共用一次操作的总请求次数与绝对时间预算，格式协商、空正文重试、暂态重试及切换已配置路由均计入实际请求。DNS、连接、超时和 HTTP `408/429/500/502/503/504` 可在同一连接、端点和模型上额外重试一次；服务的 `Retry-After` 超出剩余预算时不提前补发。鉴权、普通参数拒绝、内容拒绝和业务校验失败不作为传输故障重试。搜索参数只在服务明确不支持该参数时移除，不因网络错误改用普通请求。

请求记录保留安全的服务请求 ID、实际输出上限、用量和错误分类。已收到响应后发生取消，仍记录真实用量，业务结果不再采纳。缺少用量或价格时费用为未知；重试可能额外计费。文本响应使用绝对期限和 32 MiB 网络/解码正文上限，保留 gzip 与连接复用；关闭或超限后等待当前连接实际释放。

每次实际发送前先持久登记本地操作及请求身份，收到响应后先保存服务回执和用量，再更新费用账本。进程中断后尚无回执的请求保持“费用未知”，可结合 `model_request_started`、`model_request_finished` 日志与服务端账单核对；本地请求编号不代表服务端支持幂等扣费。记录写入失败会停止后续收费请求。记录不保存素材正文、密钥或完整端点，已有用量不会因业务失败被清零。

模型设置中的“测试此路由”只测试选中的文字路由，最多两次、每次不超过 4096 token，并继续受路由较小输出限制和共享预算控制。先验证文本正文，有剩余额度再验证结构化样本；空正文或传输补发用完额度时，未运行的协议检查保持“未确认”。样本通过不证明服务严格执行 JSON Schema、思考控制或最大容量，官方型号容量单独展示。草稿只返回临时诊断；与已保存配置一致的诊断可跨重启读取，凭据、端点、模型或有关请求参数变化时失效，不因改名或无关设置全部失效。诊断不保存密钥、其摘要或原始模型响应。

## 转写整理与时间边界

开启 LLM 转写整理后，整理正文与摘要会持久化，转写页面、整段语义分析和整场总结使用整理结果。原始 ASR 正文与词时间戳单独保留，人工修改后旧整理结果失效。整理正文没有逐词对齐信息：已有词时间戳的局部高光及成片文案继续读取对应时间范围内的原始词；覆盖完整分段时使用整理正文。没有词时间戳的局部窗口不提供无法定位的正文，完整分段仍可使用全部文本，并保留非词级精确标记。

整理失败会保留原文、词时间和失败记录。通过场次“重新分析”明确发起补做时，仍对应当前原文的失败整理复用已有转写，跳过 ASR；自动下播重分析不授予整理补做权限。人工改文、下游成果、来源变化或失效任务身份仍阻止覆盖。审核重新分析的“仅失败”筛选也包含解释失败，即使对应审核判断曾成功。

## 整场总结恢复

完整输入能放入所配置模型的容量并保留生成空间时，整场总结仍一次综合全部 ASR。超出容量时按原分段和字符范围生成摘要节点，再按顺序逐层合并、完成全场分析；分片保留原始时间范围，不按字数推算时钟。请求继续使用配置中的大输出上限，所有层和补发共享一次操作的请求次数与总时限。

成功节点单独保存，中断或失败重试时复用；单块变化只使相关节点及祖先失效。执行参数变化不删除成功缓存，模型、提示语义和实际输入变化会重新核验。明确重新生成会重做最终综合。缺失节点或预算耗尽时不发布部分总结，原请求仍最多三次失败，正常关闭不计失败次数。ASR 缺口的“部分完成”状态单独表示录音覆盖情况，不表示省略尚未总结的已有文本。

最终保存前再次核对当前请求身份、整场输入、来源名称和覆盖状态。查看时间线只显示过期或缺失，不直接增加模型请求；已有后台补偿和明确操作负责登记生成任务。

审核队列按当前筛选分页，可通过上一页、下一页浏览全部候选，计数包含全部历史记录。上传预检因文件缺失、标题或频率限制而跳过后，处理原因并重试即可重新预检；平台结果未知的任务仍须先核对。

## Web 静态资源与服务关闭

Windows 静态 JS/MJS/CSS 响应不依赖系统 MIME 映射。白屏或“添加直播间”无响应时记录浏览器控制台错误、失败资源 URL 和响应 Content-Type；服务端仍保留 HEAD、Range、缓存与 404 语义。

Windows 双端工作台通过父进程管道通知后端正常收尾。管道自身失效时，日志记录「父进程监管管道异常」及脱敏诊断；后端完成资源清理后以失败状态退出，工作台随后回收前端。正常关闭父进程管道仍按正常退出处理。

使用 `blc start`、`blc console` 或 Portable 启动时，前端或后端异常退出会先清理所属进程，再按 1、2、4 秒退避自动恢复，最多追加三次启动。连续通过就绪检查一分钟后才重置次数；初始化、清算旧录制和关闭所花的时间不计入稳定运行。人工关闭不触发重启。日志出现「所属服务清理未确认」或退出码 `75` 时停止自动恢复，保留错误供排查。整个 Launcher 或独立 console 宿主已退出时，需要重新启动程序；应用不会自行注册系统开机服务。

前端监听因端口占用、地址不可用或权限不足失败时，清理本次所属服务后直接退出，不重复启动 API。日志保留原始 socket 错误；修正地址、释放端口或恢复监听权限后重新启动。独立命令和 Portable 均以退出码 `1` 报告该失败；所属进程清理无法确认时仍优先报告 `75`。

Windows 前端及虚拟环境启动器的后代由独立 Job 管理。工作台退出或被终止后，系统回收这组前端进程并释放监听端口；后端仍通过管道关闭执行自己的资源清理。

关闭服务时先通知计算停止，再依次收尾监控、录制、Web 作业、Worker、插件及指标采样。启动失败或某一服务关闭失败仍会执行其余资源清理，并保留异常。受监管媒体命令使用独占进程树，取消、超时及主命令退出都会清理后代，不影响其他程序；关闭期间不再启动新媒体命令，中断的任务重新排队且不消耗业务重试次数。Web 作业关闭等待超时会保留运行/取消中的处理器登记并阻止新作业，不会把尚未退出的同步线程当作已完成；需要等外部请求的有限超时或处理器实际返回。`Finished server process` 仅表示服务器生命周期结束，须以实际 Python 进程退出及命令行返回确认关闭。
