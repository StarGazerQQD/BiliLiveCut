# 编辑分析模型调用

`llm.call_structured` 按调用方指定的能力选择路由；事件解释和编辑判断默认使用 `analysis`，整场总结核验使用 `summary`。请求通过 OpenAI SDK 执行，`ModelCallBudget` 将多步操作的次数与时间统一计算。既有 `call_text` 接口继续兼容原业务；编辑业务接入时必须在操作入口创建预算，并把同一实例传递给解释、判断、事实核验、上下文扩展和证据变化重算。

`new_editorial_budget` 从当前任务配置读取 `EDITORIAL_MODEL_MAX_ATTEMPTS`（默认 8，1–32）与 `EDITORIAL_MODEL_DEADLINE_S`（默认 1800 秒，1–14400）。配置在下次操作生效。每次请求同时受 `LLM_REQUEST_TIMEOUT_S` 和总剩余时间约束；SDK 自动重试关闭。并发或递归使用同一预算会报告错误。

整场总结使用 `SUMMARY_MODEL_MAX_ATTEMPTS`（默认32，1–32），生成、分批核验、正文修订和格式修复共用同一个持久操作与 `EDITORIAL_MODEL_DEADLINE_S` 绝对期限。执行前检查最低请求量，完整草稿生成后再按实际批数和容量检查剩余核验计划。自动重排、输入变化后的补偿与进程恢复继承原额度；调整配置不扩大已存在操作的授权。未确认请求仍占次数，费用保留未知。原 claim 失效后，实际回执和已知费用仍可登记，草稿与最终结果不能写回。

整场总结将全部 `Transcript.final_text` 按录制顺序一次送入生成请求，包含上传者、标题和录制时间含义；不采用 ASR 整理文本、分段摘要或滚动记忆替代原文。完整输入及核验计划无法容纳时，在请求前报告容量不足，不截断、不拆分生成。完整草稿另存，事实核验可按容量分批；页面分开展示草稿、核验状态及进度。只有核验通过才保存正式总结，已通过批次在恢复时复用，不支持的正文在同一总预算内修订后重新核验。

分段连续摘要由 `segment_summary` 在原始转写提交后独立处理，沿用“转写 LLM 整理”开关及 `transcript` 路由，在已有整理请求外增加摘要请求。每段输入按场次隔离的历史记忆、近期原文和本段原文，输出本段独立摘要、是否需要后文及带原始段号的记忆。记忆仅辅助理解，不作为原文证据；后文可帮助解歧，但不提前消费到历史记忆。容量计算包含系统说明、Schema 和输出预留，接近上限时压缩历史并保留最近两段原文重叠，压缩失败或仍超限时明确失败。

连续摘要队列和步骤使用独立的版本化 AppSetting 键，单步模型操作持久保存次数、截止期限、压缩检查点及租约。后台每次领取场次内最早可处理片段，转写尚未完成的前段等待，已终止且无原文的前段携带缺口。原文、词时间、人工校正、路由策略及前驱记忆进入来源身份；来源变化使相关后续摘要过期，尾部追加不撤销固定前缀执行。后文补充及显式重分析可重建来源有效的摘要；失败保留同来源旧成功并单独记录错误，不把不同来源的旧正文标为当前成功。取消及重启复用原操作和已付费压缩检查点。转写 API 和页面统一使用 `summary` 并展示 pending/running/stale/ready/failed 状态，原文和词时间不改写。

核验回传程序提供的稳定原文编号，完整材料不按前32项截断。批次结合候选正文大小、路由容量及剩余请求数规划。总结和事件结构化调用统一支持最多 2 MiB 的本地输入载荷；各阶段仍按正式发送的系统说明、Schema、素材、候选和修复消息计算模型容量，输出遵守配置、路由和原厂型号限制。字节数是保守容量估算，不是服务商 tokenizer 的精确 token 数。

成功节点在检查剩余预算之前读取，完整根节点可在预算耗尽后零请求提交。次数、期限或每日限额阻止新请求时，页面显示失败及人工重新生成提示；人工点击整场重新生成或明确发起场次重分析才建立新预算，成功的素材节点继续复用。成功请求保留 completed 身份，旧格式活动请求保留原记录并要求人工重新生成，不推断历史费用或自动重授额度。

默认请求严格 `json_schema`。官方 `api.deepseek.com` 的 Chat Completions 按其[官方接口支持范围](https://api-docs.deepseek.com/api/create-chat-completion/)直接请求 `json_object`；精确核对服务域名，代理和其他兼容端点不会因为模型名包含 DeepSeek 就采用此规则。仅当服务以 400/422 明确报告不支持响应格式时，按当前协议继续尝试 `json_object`、普通文本模式（不发送 `response_format` 参数，诊断记录为 `text`）；所有协议仍经过同一标准 JSON 解析器和调用方的严格字段、引用及业务校验。Schema 内容错误、其他参数错误、认证、限流、网络错误不触发格式降级。该协商记录限于一次操作，不将一个模型的结论推广到其他路由或模型。

事件解释、事实核验及编辑判断分别按实际输入和阶段身份允许一次格式/引用修复；普通未指定作用域的调用保留整次操作一次修复的规则。一次空正文重试和一次上下文扩展仍受整次操作约束。总结分批核验按候选、上下文、模式和完整原文内容哈希各允许一次格式修复，该许可持久保存；回队、重启和路由切换不重新授予。同一总次数、费用与时间预算始终生效。修复回传的上次失败正文位于单独的不可信用户消息，不能作为事实依据；系统说明不接受素材中的指令。

事件判断默认使用前后各180秒的材料，可按明确方向最多扩展到600秒。判断扩展后，仅在实际材料身份不同时刷新解释及事实核验，继续使用原操作预算；正常扩展路径共6次请求，未扩展路径不增加请求。已保存的当前扩展解释可以直接复用，避免先生成随后丢弃的基础解释。基础事件身份与完整实际材料身份分别保存，提交前同时检查；基础窗口外的文字变化也会使扩展解释失效。判断后的解释请求保存为连续的后续请求记录，界面与评估导出纳入真实用量。

精确词级材料同时提供片内、前文与后文摘录，完整上下文继续保留；缺少词级时间时不按字符比例猜测。模型的独立理解判断必须针对建议范围或目标范围，所引内容须已定位且完整进入该范围。两条成片链共用实际边界确认，建议无法应用、媒体不可用、范围不覆盖或素材截断时，实际成片独立性保持未知；原模型判断仍单独保留。候选范围后续改变会使原确认失效。历史策略的合法执行记录继续可读，旧记录不能凭历史完整标记自动批准。

路由 `deepseek_search_enabled=true` 时，业务执行先请求官方 `POST https://api.deepseek.com/v1/tools/search`，再调用已配置的生成模型。查询取调用方素材规范化后的前 128 个 Unicode 字符，固定 `count=10`、`need_content=false`；搜索响应上限 8 MiB，不自动重试、不跟随重定向、不抓取结果页面。取消、连接授权、每日估算限额、次数与绝对期限仍在发送边界检查。结构化输出修复复用本次搜索参考，不重复搜索；搜索失败不会降级成无来源生成。

搜索请求以 `purpose=search`、`protocol=search` 进入同一持久账本，`output_tokens_limit=null`，未提供的用量和费用保持未知。回执后的来源元数据使用 `SearchEvidence` 版本 1 保存实际采集时间、来源编号、标题、URL 和可空的 UTC 发布时间，写入失败阻止后续生成；账本不保存搜索查询或素材正文。生成中的 `S*` 搜索编号不能代替审核输入的 `E*` 原始证据引用。趋势只接纳本次实际来源 URL，新增和重复条目更新均保存可回读来源；旧条目缺少该字段时保持未知。搜索配置进入解释、编辑判断、总结和整理的策略指纹，历史未开启配置保持原有缺省形态。

解释请求的 Schema 使用本次实际配置的标题、摘要和实体上限，本地仍执行相同严格校验。日志及公共诊断只展示 Schema 已知字段路径、固定错误类型和经审查的固定业务原因，数组位置统一显示 `[]`；未知字段、联合类型标签与输入值不回显。诊断最多四项、240 字符。修复请求在独立不可信用户 JSON 内同时提供 `previous_invalid_output` 和 `validation_feedback`，后者包含准确数组位置、数值限制或当前合法 E/Q 配对，帮助模型针对错误修正；这些原文及具体引用不进入日志、公共结果或请求账本。

请求 Schema 枚举本次 `available`/`degraded` 证据的完整 ID，并要求逐字复制；事实核验进一步限定为已通过解释校验且真正提供的引用，建议边界进一步限定为有时间定位的可引用证据。扩展上下文后按新输入重新生成枚举。没有可引用证据时，解释在发送前报告上下文不可用；待复核判断仍允许空引用，没有可定位证据时建议边界只能为 `null`。本地继续严格核对状态、引用、原文与时间，不修补错误引用。

请求使用独占的异步客户端，在同步分析执行线程内运行。取消与绝对截止时间会中断等待并关闭本次连接，确认请求协程退出后才返回，不遗留本地后台请求。资源清理可能继续占用时间，期间不再发送后续请求。已经发送给服务商的任务不能保证撤销，最终计费仍以服务商账单为准。单个 HTTP 成功响应最多读取 32 MiB；业务 JSON 最多 16 MiB，各结构化阶段的源输入最多 2 MiB。请求 Schema 独立限制为 4160 KiB，可容纳主引用和边界引用两份合法源 ID 集合及模式自身。字节上限仅是本地载荷限制，实际输入和输出还按全局配置、路由与型号容量及剩余上下文计算，不增加总请求次数或时间预算。

发送前和收到响应后检查最新连接授权。已撤销连接不再回退到其他路由，也不采用已返回的业务结果。每次实际请求记录请求模型、服务报告模型、格式、用途、耗时、错误及服务返回的用量。拒绝、截断和格式错误响应同样记录已知成本；推理过程不写入正文或诊断。

事件解释的鉴权失败缓存另存连接级授权序号。连接密钥、规范化地址、启用状态或存在性改变时，同一配置事务更新序号；普通重试可重新验证新授权。显示名称、无关配置和相同密钥保存不使失败缓存失效。成功解释继续按证据与语义策略复用，换 Key 不触发重新收费。旧任务保留配套的旧 Key 与旧序号；迟到的旧授权失败不能覆盖新授权或已经成功的解释。序号不包含凭据及其摘要，删除连接后仍保留，避免复用 ID 时恢复旧身份。

强制重算事件解释失败时，只有当前版本、策略、完整证据束和非空实际来源指纹全部相同的已成功解释才会保留，后续评分按缓存命中读取该成功结果。失败请求仍消耗本次预算并记录失败；提交时再次阻止迟到失败覆盖同来源成功，不将旧策略或不同证据的成功冒充当前结果。

已知的长度上限结束、拒答和工具调用分别使用本地固定诊断，未知结束原因保持泛化。服务给出的原始结束字段或拒答正文不回显；旧记录没有保留具体结束原因时，不能根据 token 用量补写截断结论。

失败请求同时保存可选的有界诊断：错误类别、本地生成的说明、HTTP 状态及经过过滤的服务错误码、参数名和请求标识。DNS、连接、超时、HTTP 拒绝与输出校验失败分别标识；原始响应、服务错误正文、异常文本和凭据均不保存。请求日志以 WARNING 记录相同定位字段，界面的模型调用详情展示可用诊断。历史记录缺少诊断字段时仍能读取；网络故障需要结合 DNS 与服务可用性排查，协议调整不能替代网络修复。

候选分析先提交本轮检测与 ASR 事实，再在 SQL 事务外、原任务租约内执行首次解释和编辑判断。整批提交遇到真实变化时仍有限重算：未变化草稿须通过租约、目标身份、证据、编辑输入、成片策略及媒体文件身份校验才可复用；变化事件继续使用原共享预算。任务处理耗时包括模型调用及重算。媒体路径和 stat 身份只进入本地成片指纹，不发送给模型。

所有请求前检查既有每日账本，账本故障直接停止。成本仅在实际输入/输出用量与有效价格齐备时估算；缺失用量或未配置价格保留 `null`，不能声称零成本。每日限额仍是估算护栏，未知用量与并发请求使其无法替代服务商账户硬限额。总请求次数和时间上限始终生效。

验收使用真实 SDK 与受控 HTTP 边界，并保留本机真实回环 HTTP 集成测试。不需要提供商密钥，不用模拟模型结果宣称真实剪辑质量提高。
