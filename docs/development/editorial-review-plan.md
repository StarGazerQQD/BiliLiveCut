## 核心设计约束

### 编辑判断和执行结果

编辑结论使用 `recommend`、`reject`、`needs_review`；请求失败时不伪造结论。兴趣等级为 0–4 的序数值，可为空，不能解释为概率。独立成片能力和语义完整性在证据不足时保持未知。

结果保留版本、吸引点、判断依据、引用证据、独立可理解性、边界状态、可选建议边界和不确定性。缺失上下文明确区分前文、后文及两者。建议边界必须落在真实、连续且可访问的录制范围；文本证据没有精确时间时不得伪造秒级定位。

执行结果另行保存提供商、模型、尝试、耗时、使用量和错误分类。业务结论、技术错误、解释来源及人工状态互不替代。所有重试共享预算，格式修复和上下文扩展不能绕过已有路由、取消及凭据撤销机制。

### 证据、提示与缓存

输入使用统一的场次相对时间，记录证据范围、精度、来源和截断状态。录播内容、弹幕与转写均视为不可信输入，不能改变系统规则或扩展工具权限。弹幕只证明观众发言，不能直接作为主播行为的事实。

限制完整序列化输入的大小，保留必要上下文及证据身份；不能只截断正文而遗漏详情字段。字词覆盖率只作为诊断信息，不单独判定摘要真伪。缺失或失败使用明确中性说明，不用热度模板伪造内容总结。

缓存身份覆盖证据、模型及能力路由、提示与策略版本、相关配置。指纹和日志不包含凭据。成功结果与失败状态分别处理；有限重试不能造成每次页面读取重新计费。

### 存储、作业与人工保护

优先使用已有版本化 JSON 扩展点，维持现行数据库格式和应用版本分离。确需物理模式变化时，必须先形成完整兼容与迁移设计，不自动迁移用户数据库。

远端调用在数据库事务之外执行。提交阶段统一验证当前输入、配置、租约、取消及人工状态，并原子提交结果。重新分析使用已有作业机制，不删除再创建候选。人工认领即受保护，无草稿的有效认领同样不能被覆盖。

机器建议保留与人工决定的区别。重新分析造成推荐与拒绝互转时维护原有业务身份，按现有任务状态机处理未开始的下游工作，不能撤销已发生的人工操作或发布行为。

### 界面与质量

时间线和复核界面使用同一解释记录；明确展示解释失败、待复核及证据不足。热点 ID、候选 ID、复核事件 ID 分别使用，链接指向真实对象。热点跨度和剪辑时长分别标注；普通音频信号不统一标为峰值。

复核权限和盲审仍适用，新增字段不能旁路隐藏分数与机器建议的规则。修改后按现有 SSE 通知及 HTTP 查询恢复状态，保留用户未提交的复核内容。整场总结与逐事件编辑判断保持独立。

评估保存输入、策略、模型、配置、版本和运行成本；按完整场次划分调试与独立评估集。固定候选评估不能冒充全场召回率。没有适用标注或真实调用时，明确记录缺失，不能用模拟结果宣称真实质量提高。

2026-10-26 验收范围调整：用户明确说明本机无法承担真实录播和分析、目前没有可用素材与人工标注。真实素材质量验收延期至用户反馈后单独执行，不阻塞本次任务和 PR 交付。P7 仍须完成评估工具、输入校验、指标计算、可复现记录与工程测试；实际精确率、召回率、事实性和模型效果记录为“延期验收”，不得填入虚构数值或宣称通过。

## 基线审查与接口安排

- 新领域契约放在 `app/analysis/editorial_contracts.py`，使用已有 Pydantic，保持输入、业务结论与执行状态分离，不依赖 Web 或数据库。模型引用与时间边界在结构校验后再次和原始输入交叉核验。
- `app/analysis/llm.py` 保留现有文本接口，增加可诊断、共享预算的调用入口。编辑请求使用当前 `analysis` 能力路由，配置快照与调用前授权继续遵守现有模型目录。
- 事件入口仍为 `app/pipeline/workers/analyze.py`，在已有事务外计算、事务内核验和提交的边界中接入。旧片段路径也使用同一编辑契约，不能只改时间线文案。
- 解释、编辑建议和执行记录通过现有版本化 JSON 字段保存，数据库格式版本保持 6；不得覆盖 `_review_workflow`、人工边界、认领信息或历史。正式接口只投影经过校验且当前角色可见的字段。
- 重新分析复用 `app/jobs`、`app/db/job_store.py` 和业务处理器注册入口。结果提交与作业终态共用事务，提交前再次验证任务代次、证据、相关配置与人工状态。
- 技术分数保留其技术意义，兴趣等级单独保存，不将 0–4 等级直接当成概率融合。机器拒绝及待复核必须进入批准检查，人工明确决定保留优先权。
- 页面读取只查询已持久化的逐事件结果；前端变更同步 OpenAPI、生成类型、HTTP 查询恢复及现有通知，不通过 GET 发起编辑模型调用。

已确认的基线问题包括：事件完整度由时长公式生成；模型文本接口不能区分多种失败；低热度上限可能压制有价值的安静内容；部分重新分析删除再创建自动候选；无草稿的有效人工认领未被该删除路径保护；热点时段与成片时长缺少清晰区分。

## 阶段验收与发布边界

每个阶段按目标测试、必要完整测试、Ruff、已配置类型和其他质量检查、相关构建与制品检查、内容一致性及实际 diff 的顺序验收。跨模块关键阶段以及最后一次修改后的最终验收必须运行完整测试集。没有适用检查时明确记录 N/A 及理由；工具、权限或依赖故障不能记为 N/A。

最终覆盖 Python、前端、文档、Portable、源码包与 wheel、相关 Linux 和真实 Docker 路径。安全检查包括输入注入、证据和边界伪造、权限、并发写入、超大输入、重试成本、秘密泄漏和依赖风险。仅保留用户已明确接受并可逐项核对的旧系统库风险，新增风险不得自动豁免。

构建产物记录实际文件名、版本、大小、SHA-256 与 CRC32，并检查源码和构建提交、Payload 身份、敏感信息及缓存泄漏。构建通过不代表获得发布授权。本次不创建标签、不移动已有标签、不合并 PR，也不发布 Release。
