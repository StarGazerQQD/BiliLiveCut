# 编辑判断领域契约

`app/analysis/editorial_contracts.py` 定义编辑判断的输入、业务结果和执行记录，使用已有 Pydantic 校验，不读取配置或数据库，不调用模型。此契约是分析链接入的基础；引入契约本身不改变候选或批准行为。

## 输入

`EditorialReviewInputV1` 的时间基准固定为 `session_seconds`。`target` 记录来源类型、场次、对象 ID、稳定业务键、事件范围与峰值；`window` 记录实际提交给模型的范围。`recording_ranges` 必须按时间排序，预先合并连续范围，不能让输入跨过断流缺口。窗口未包含完整事件时，必须设置 `truncated`。

证据 ID 唯一，每项保留类型、可用状态、起止时间、精度、上下文位置、正文和允许的诊断字段。未知时间使用 `null`，位置与精度均为 `unknown`；不得用 0 表示未知。前文和后文必须与事件范围符合。正文、列表、字段以及完整 UTF-8 JSON 都有上限，完整输入最多 65,536 字节；详情同样计入限制。

可用证据需要实际正文或测量指标。关闭、缺失、错误与待处理证据不参与判断引用。录播及弹幕内容仍属于不可信数据，结构校验不会授予其中指令任何权限，也不证明内容的事实性。

## 业务结果

`EditorialReviewResultV1` 必须显式给出全部字段，版本为 `editorial-review-v1`：

| 字段 | 语义与约束 |
| --- | --- |
| `verdict` | `recommend`、`reject` 或 `needs_review` |
| `interest_rating` | 0–4 的整数等级或 `null`；拒绝布尔值、字符串、小数和非法数值，不作为概率 |
| `hook` | 吸引点，最多 120 字符；推荐必须非空 |
| `reason` | 非空判断依据，最多 240 字符 |
| `evidence_ids` | 无重复证据引用，最多 32 项；推荐与拒绝必须有实际可用证据 |
| `standalone` | 是否可独立理解，未知为 `null` |
| `boundary_status` | `complete`、`needs_expansion` 或 `uncertain`；完整必须同时可独立理解 |
| `suggested_bounds` | 可选起止秒数及证据引用；引用必须属于判断证据并具有时间定位 |
| `missing_context` | 扩展时为 `before`、`after` 或 `both`，其他情况为空 |
| `uncertainties` | 最多 12 项，每项最多 240 字符；待复核必须说明不确定因素 |

解析器使用标准 JSON 组件，拒绝代码围栏、重复字段、额外字段、非有限数值与超过 16,384 字节的输出。结构验证之后，必须用 `validate_review_evidence` 对照原始输入检查引用和建议范围。建议范围不能超出实际上下文或跨越断流，必须覆盖目标事件，并与引用的时间证据相交。只有降级证据时保留人工复核状态。

这些检查验证结构和可追溯性。事实支持、证据可靠性及边界建议是否适合实际剪辑仍须在业务层验证，不能仅凭符合模式就宣称内容正确。

## 执行结果

`EditorialExecutionV1` 与业务结果分开保存。`succeeded` 才可携带编辑结果，并需要真实成功请求记录；失败、关闭或取消保持 `result=null`，同时保存错误分类。执行记录不包含人工结论、认领、草稿、凭据、服务地址、原始模型正文或异常堆栈。

每次尝试记录连续序号、用途、提供商和模型标识、协议、状态、错误分类、耗时及服务报告的用量。`model` 保留请求模型，`reported_model` 保存服务实际报告的模型，未报告时为空。服务没有返回的 token 数或成本保持 `null`；不能把未知成本写成 0。`estimated_cost_usd` 仅表示按配置价格估算，并非提供商最终账单。总耗时不能少于串行请求耗时。

记录可编码到现有版本化 JSON 字段。契约不新增数据库列，不改变数据库格式版本 6；调用方写回时必须保留无关特征和 `_review_workflow`。旧记录的兼容投影由实际业务接入负责，不直接把旧规则评分转换成新的编辑判断。
