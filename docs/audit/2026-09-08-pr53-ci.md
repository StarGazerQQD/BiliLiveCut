# PR #53 CodeQL 告警修复与本地验收

版本保持 `v0.1.18.2-Alpha`，更新已有 [PR #53](https://github.com/StarGazerQQD/BiliLiveCut/pull/53)。本记录承接首次版本验收，保留此前报告作为历史证据。

## 失败证据与修复

原提交 `ea9f0775270b4dcd6fa470d5db11d7de2fe85562` 的 [CodeQL 检查](https://github.com/StarGazerQQD/BiliLiveCut/runs/101968794747) 报告一条 high 告警：`app/analysis/llm.py:149` 直接用 SHA-256 为 API Key 生成缓存摘要，触发 `py/weak-sensitive-data-hashing`。Python 与 JavaScript 扫描作业成功，但扫描结果门禁失败；原提交的其他适用 CI 检查均成功。

客户端缓存仅需判断连接配置是否一致，无需保存用于识别凭据的摘要。现改为按服务商 ID 和地址索引，在缓存锁内用 `hmac.compare_digest` 比较 SDK 已持有的完整密钥 UTF-8 字节。不同长度和非 ASCII 密钥均支持；密钥及其摘要不进入缓存键。新客户端构造成功后才退休同服务商的旧连接，最后一个活动请求成功或异常退出后关闭旧连接。未新增依赖或配置，没有屏蔽 CodeQL 规则。

新增 `tests/unit/test_llm_client_cache.py`，覆盖配置相同复用、模型变化仍复用、同前缀密钥轮换、非 ASCII 密钥、地址变更、不同服务商隔离、替代构造失败保留旧连接，以及两个活动请求中最后一个异常退出时的退休行为。独立只读复核确认实际 diff 与线程清理符合上述语义。

Portable 当前源码基线为 `9503421923233c5613989d97b9f8bc17a2e01490`。版本注册、模型锁顶层源码身份、Launcher、运行时、Payload Manifest、构建注释及文档已同步。模型内容、Schema 与应用版本未改变；Fixture 元数据根据实际重建 ZIP 更新。
